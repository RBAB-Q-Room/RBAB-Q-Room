# Waiting Guest

Digital Waiting Guest system for Rixos Bab Al Bahr. Reception creates a Waiting Guest once. The system generates the Waiting Guest number and a unique QR code, the Rooms Controller manages the live queue, the guest follows their room status on their QR page, and Reception completes the record.

It runs entirely on **Google Apps Script with a Google Sheet as the database**. There is no server to rent.

> **Status: pilot build.** Reservation and room data come from CSV imports (or mock demo data). There is **no Opera Cloud integration**. The app does not pretend to be connected to Opera.

**To deploy: follow [docs/DEPLOY.md](docs/DEPLOY.md).** No coding needed.

## Where the information comes from

| Data | Source today | Later |
| --- | --- | --- |
| Reservations | Admin uploads the Opera **arrivals report saved as CSV** (preview, then confirm) | Opera Cloud API behind the same `ReservationSource` interface |
| Missing reservation | Reception enters it manually (record flagged **Manual entry**) | still available as a fallback |
| Rooms and housekeeping status | Admin uploads a rooms CSV | Opera room status |
| Waiting Guests, history, timestamps | Created in the app, stored in the Sheet | unchanged |

Only `ReservationSource` (in `src/server/60-waiting.js`) reads reservations, so adding Opera later does not touch the rest of the app.

## The three experiences

* **Reception** (`reception` role): search by confirmation number (arrivals) or by name / confirmation / WG number (returning guests), review the auto-filled reservation, enter only luggage tag, associate, preferences and remarks, create. Shows the QR to scan. Verifies and completes when the guest returns. Can edit details or cancel a record made by mistake.
* **Rooms Controller** (`rooms_controller`): dense live queue with a prominent waiting timer, preferences and remarks, room picker (matching type first), status steps, priority, cancel.
* **Guest** (no login): mobile page opened from the QR. "Your room is being prepared" changes to "Your room is ready" on the same link. Shows resort information cards, hotel map and website links.
* **Admin** (`admin`): user management, arrivals and rooms CSV import, live figures, CSV export of every timestamp.

Statuses: Waiting, Room Assigned, Room Being Prepared, Room Ready, Guest Returned, Completed (plus Cancelled for mistakes). Every transition is timestamped and logged with who did it.

## How it is built

```
src/server/*.js     server code (Apps Script V8). Bundled into one Code.gs
src/web/            browser app (HTML/CSS/JS), inlined into one Index.html
src/vendor/         qrcode-generator (MIT), used server-side so nothing leaves Google
scripts/build.js    npm run build  ->  dist/apps-script/{Code.gs, Index.html, appsscript.json}
dev/                local dev server + a fake of Google Sheets/Apps Script used for testing
tests/              automated tests (run the real bundled Code.gs against the fake)
docs/DEPLOY.md      step by step deployment
```

* **One source of truth**: the `WaitingGuests` tab. Every change goes through one function layer, runs under a script lock (so two people cannot take the same room or number), is logged in `StatusHistory`, and bumps a version counter. Screens poll that counter every 4 to 8 seconds and refetch only when it changes.
* **Sheets pitfalls handled**: every cell is plain text, so Google never turns `2026-09-29` into a date, drops a leading zero from a phone number, rounds a long confirmation number, or evaluates `=...` as a formula. Exports neutralise formulas.
* **Security**: guest links carry a 244-bit random token; the guest API returns a fixed whitelist of fields (no phone, email, staff notes, associate, luggage tag or room number); staff endpoints need a session and the right role; passwords are salted and hashed and generated by an admin; failed logins are throttled; sessions are stored hashed; no secrets are in the repo.
* **Opera later**: implement `ReservationSource` (and a room source) against Opera; the rest is unchanged.
* **Analytics**: real timestamps for guest arrival, created, room assigned, preparation started, room ready, guest notified, guest returned and completed. The overview shows only values computed from real records.

## Develop and test

```
npm install
npm test           # 30+ automated tests against the real bundled server code
npm run build      # regenerate dist/apps-script (commit the result)
npm run dev        # http://localhost:3000, demo data, fake Google Sheet in dev/data.json
```

`npm run dev` prints demo logins on first start (random passwords; set `WG_DEV_PASSWORD` to choose one). `node dev/e2e.js` drives the UI in a real browser (needs Playwright).

Automated tests cannot run inside Google itself. After deploying, run **`runSelfTest`** in the Apps Script editor; it exercises the real Google environment and cleans up after itself.

## Not built (by design)

WhatsApp, SMS, Opera Cloud integration, real hotel data, payments, production hardening beyond a pilot.
